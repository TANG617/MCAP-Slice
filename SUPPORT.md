## Before opening an issue

1. Read the [User Guide](docs/USER_GUIDE.md), especially Troubleshooting.
2. Search [existing issues](https://github.com/TANG617/MCAP-Slice/issues).
3. Confirm that the problem still occurs with the latest package available for
   your platform.
4. If possible, reproduce it with a synthetic or redistributable MCAP.

## Bug reports

Open the
[issue tracker](https://github.com/TANG617/MCAP-Slice/issues), choose
**New issue**, select **Bug report**, and include:

- operating system and architecture;
- application package or source-build details;
- steps to reproduce;
- expected and actual behavior;
- relevant error text; and
- whether the MCAP contains compatible video, top-level Metadata, or duplicate
  topic names.

Never upload a private recording unless you have explicit permission to
redistribute it. Prefer a minimal synthetic file. Remove usernames, absolute
paths, credentials, and customer information from logs and screenshots.

## Feature requests

Open the
[issue tracker](https://github.com/TANG617/MCAP-Slice/issues), choose
**New issue**, and select **Feature request**. Describe the workflow problem
first, then the proposed behavior. Include how the request should interact with
time boundaries, topic selection, Metadata, and existing MCAP files when
relevant.

## Questions

Questions that may help other users can be opened as GitHub Issues. Include
enough context for someone without access to your recording or environment to
understand the problem.

## Security vulnerabilities

Do not disclose a suspected vulnerability in a public issue. Follow
[SECURITY.md](SECURITY.md).

Support is provided by project maintainers and contributors on a best-effort
basis. No response-time or compatibility SLA is implied.
